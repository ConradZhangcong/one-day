# One Day 产品需求文档

> 版本：MVP v1（整理版）  
> 状态：实施中  
> 更新日期：2026-08-31

## 1. 产品概述

One Day 是一款面向个人轻量规划用户的本地优先待办与日历 Web/PWA。它帮助用户快速记录任务、安排执行时间、管理截止时间、处理错过事项，并逐步通过重复事项与多维日历理解时间负载。

产品要完成的核心闭环是：**记录 → 整理 → 安排 → 提醒 → 完成、跳过或重新安排 → 回顾**。

## 2. 用户与价值

目标用户是希望统一管理工作、学习及生活待办，但不需要复杂项目管理体系的个人用户，例如职场人士、学生与自由职业者。

用户价值：

- 以标题快速创建任务，不被复杂字段打断。
- 清楚区分“何时做”和“最晚何时完成”。
- 通过恢复入口处理错过计划或逾期事项，而不是被系统静默改期。
- 使用易理解、可预测的固定重复规则。
- 在议程及日、周、月、年视图中理解近期安排和长期节奏。

## 3. 产品原则

- **渐进式呈现**：快速新增只要求标题；详情中再补充组织与时间信息。
- **显式恢复**：错过计划与逾期均保留原始时间，用户自行决定完成、跳过或改期。
- **可预测重复**：保存前预览发生日期；每次操作清晰标注影响“仅本次”或“整个系列”。
- **同一事实来源**：列表、恢复区和所有日历视图展示一致的任务、实例与状态。
- **本地与用户控制**：数据默认只留在设备；导出、恢复及未来同步或 AI 能力都必须由用户主动触发。

## 4. 当前已实现能力

### 4.1 任务与组织

- 快速新增、编辑、删除、完成、跳过，以及普通单次任务的撤销完成。
- 系统收件箱与自定义一级清单；清单支持创建、重命名、排序、归档和删除确认。
- 删除自定义清单时，其中任务迁移至收件箱，不级联删除。
- 多标签、无/低/中/高四档优先级、备注及组合筛选。
- 收件箱、今天、即将到来、已完成及自定义清单视图。

### 4.2 时间、恢复与提醒

- 计划执行时间与截止时间可独立设置，均支持全天日期或精确本地时间。
- 校验截止时间不得早于计划时间。
- 提供互斥的“错过计划”和“已逾期”恢复视图；两者均保留原时间，可完成、跳过或重新安排。
- 提供日、周只读回顾，展示完成、跳过、错过计划和仍逾期事项。
- 提醒可关联计划或截止时间，支持提前提醒、全天默认提醒时间和稍后提醒。
- 在页面可见且浏览器允许执行时，提醒目标时间后 60 秒内至多触发一次；应用恢复后仅补发过去 15 分钟内未送达的提醒。

### 4.3 基础体验与数据

- 响应式 Web 界面、浅色/深色主题、键盘流与文字缩放支持。
- 任务与设置存储在当前浏览器的 IndexedDB；无需账号。
- PWA 应用外壳与离线基础能力已具备。
- 用户时区显式管理；应用不会因设备时区变化而静默移动日期。

## 5. MVP 待交付需求

### 5.1 固定重复事项

- 支持每 N 天、周、月、年重复；每周可选多个星期；每月支持固定日期和每月最后一天。
- 支持永久、截止日期和发生次数三种结束条件，并在保存前预览最多未来三次发生日期。
- 重复系列以计划时间为优先锚点；仅有截止时以截止为锚点；两者皆无时，必须先指定首次计划日期。
- 一个普通系列在任意时刻只保留一个活跃待处理实例。连续漏做不会生成逾期堆积；处理当前实例后直接推进到下一未来合法发生日期。
- 当前活跃实例可完成、跳过或“仅本次”改期；未来投影只读。修改规则或系列模板必须再次确认其影响范围。
- 支持暂停、恢复和停止整个系列；已完成/跳过历史须保留。永久删除历史必须经危险操作确认。
- 不支持按实际完成时间重复、节假日顺延、农历重复或“本次及以后”编辑。

### 5.2 议程与多维日历

- 提供议程、日、周、月、年视图。
- 日视图包含全天区和时间轴；没有时长的定时事项显示为时间点。
- 周视图以周一为首日，显示七天安排、全天事项和每日计划负载。
- 月视图显示有限数量任务标签，溢出项用 `+N` 展开；年视图以热力图或紧凑标记展示负载密度和完成活动，且均可下钻到日期详情。
- 仅有截止的任务显示截止标记，不能伪装为计划时间块。
- 从日历可创建、打开、完成、跳过或重新安排普通任务和当前重复实例；拖动改期始终是“仅本次”。
- 计划负载定义为本地日期内待处理计划实例数量；完成活动定义为该日期内实际完成的任务或实例数量。

### 5.3 备份、恢复与发布加固

- 导出包含格式版本、导出时刻、时区及全部领域数据的完整 JSON 备份。
- 恢复前校验格式和数据、展示替换摘要并要求确认。
- 恢复采用整库替换；任一错误必须完整回滚，原数据不变。
- 完成 PWA 安装、离线重启、升级提示与主流浏览器及移动视口验证。
- 在产品内说明清除站点数据、卸载或设备损坏会导致本地数据丢失，并引导定期备份。

## 6. 明确不在 MVP 范围内

- 账号、云备份、多设备同步、冲突解决、服务端可靠推送与外部日历同步。
- 原生移动或桌面客户端。
- 项目层级、嵌套清单、子任务、依赖、附件、团队协作、权限、指派与评论。
- 习惯打卡、日记、番茄钟、看板、甘特图及复杂统计。
- AI 分析、自动排程，或任何未经确认的数据上传。
- 完整 RFC 重复规则、按完成时间重复、节假日调整、农历及单任务独立时区。

## 7. MVP 验收标准

1. 用户无需进入高级设置，即可创建仅含标题的任务，并在收件箱中找到、补充时间并完成它。
2. 无日期、全天计划、精确计划、仅截止、同时有计划和截止的任务均出现在正确列表与日历位置；非法时间顺序不能保存。
3. 计划已过但截止未到时仅显示“错过计划”；截止经过后仅进入“已逾期”主恢复分组。
4. 重复预览、议程和各日历视图对同一范围生成一致的发生实例；查询范围变化不得改变重复相位或次数限制。
5. 仅当前活跃重复实例可完成、跳过或单次改期，且不会影响后续固定周期；未来投影只读。
6. 议程、日、周、月、年视图均可下钻到任务详情，汇总指标与明细数量一致。
7. 列表与日历操作立即在其他相关视图反映，且共用同一任务事实来源。
8. 数据重启后仍存在；核心流程离线可用；状态表达不只依赖颜色。
9. 在桌面和手机宽度均可完成核心流程，并支持键盘与文字缩放。
10. 平台支持时可安装 PWA；完整 JSON 可导出并安全整库恢复，非法或失败恢复不得改动原数据。

## 8. 关键约束与风险

- 第一版为本地优先产品，浏览器后台限制意味着提醒只能在平台允许范围内尽力送达，不能承诺应用完全关闭后的准时通知。
- 全天日期和重复规则必须按用户配置的 IANA 时区计算，不能因 UTC 转换或旅行而改变日期。
- 重复投影、日历和提醒必须复用统一领域规则，避免各视图出现不一致。
- 数据库迁移、备份格式、发生实例标识和 Service Worker 缓存是高风险区域，必须具备回归测试和可恢复策略。
