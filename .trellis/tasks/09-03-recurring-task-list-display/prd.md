# 优化重复任务列表展示

## Goal

减少长期重复事项在“即将到来”中的视觉噪音，并让“今天”中的普通任务和重复实例使用一致、可辨识的展示方式，使用户既能聚焦下一次行动，也能看见当天已经完成的工作及其完成时间。

## Background

- `TodoService.snapshot()` 当前查询从今天起 90 天的 occurrence 投影；“即将到来”逐条渲染同一系列的所有未来虚拟实例，长期系列会占据大量列表空间。
- “今天”先渲染普通任务、再渲染重复实例，两类行的清单、优先级、标签和状态信息不一致，也没有统一按计划时间排列。
- 普通任务实体和 occurrence 历史均已保存 `completedAt` Instant，但 `TaskOccurrenceView` 没有携带完成时间，Todo occurrence 快照也未包含历史记录。
- 既有重复模型保持“一个活跃实例 + 只读未来投影 + 历史记录”；未来实例仍不可提前操作。

## Requirements

1. “即将到来”对重复 occurrence 按 `seriesId` 折叠；每个系列在现有筛选条件下只显示日期最早的一条，普通任务保持逐条显示。
2. 折叠只改变 Todo 列表展示，不写入数据、不改变 occurrence projector、日历范围展示或系列推进语义。
3. “今天”把普通任务与重复实例投影成一致的任务行，按主要计划/截止时间稳定排序，不再按任务类型分成前后两段。
4. 两类任务行都展示可见的状态文字、计划/截止信息、所属清单、优先级和标签；重复实例另有明确“重复”标识，并继续区分当前可操作实例与未来只读实例。
5. “今天”默认同时展示安排在今天的待处理项和已完成项；显式选择状态筛选时只展示该状态。已跳过项仍只在显式筛选“已跳过”时出现。
6. 已完成的普通任务和重复实例都展示“已完成”标识，以及按应用 IANA 时区格式化的本地完成时间。今天页用 `HH:mm` 表达即可，并带可理解的“完成于”文字。
7. 已完成重复实例保持只读；不新增撤销 occurrence 完成、操作未来 occurrence 或修改重复规则的能力。
8. 保持现有搜索、日期、清单、标签、优先级和状态筛选对普通任务与重复实例一致生效。

## Technical Notes

- 完成时间来自已验证的领域 `Instant`，通过应用层 `TaskOccurrenceView` 传递；React 组件不读取 Dexie record。
- Todo 快照需要包含今天范围内的 occurrence 历史，同时保留当前 90 天未来投影窗口。
- 列表折叠和统一排序应使用纯展示投影函数并添加单元测试，避免在 JSX 中散落分组逻辑。

## Acceptance Criteria

- [ ] 同一重复系列在“即将到来”命中多个未来日期时只出现最早一条；两个不同系列各出现一条，普通任务不被折叠。
- [ ] 搜索或其他筛选排除系列最近一条、但命中其后续 occurrence 时，仍显示筛选结果中最早的那一条。
- [ ] “今天”默认同时显示当天待处理和已完成的普通任务、重复实例；显式状态筛选严格返回所选状态。
- [ ] 今天列表按主要计划/截止时间稳定排列，普通任务与重复实例交错展示，且两者共享清单、优先级、标签与状态表达。
- [ ] 普通任务和重复实例完成后都显示“已完成”和应用时区下的完成时刻；待处理项不显示完成时间。
- [ ] 已完成 occurrence 不提供完成、跳过或改期操作；未来虚拟 occurrence 仍只读。
- [ ] 相关投影、应用查询和组件行为有回归测试；format、lint、typecheck、全量测试和生产构建通过。

## Out of Scope

- 改变日历中未来 occurrence 的逐项展示。
- 新增手动展开“即将到来”某个系列的全部 occurrence。
- 修改重复规则、物化策略、数据库 schema 或 occurrence key。
- 为已完成重复实例新增撤销完成能力。
- 重设计收件箱、清单页、已完成页或恢复页的产品语义。
