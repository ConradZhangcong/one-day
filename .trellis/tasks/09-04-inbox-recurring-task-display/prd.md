# 收件箱重复任务折叠与醒目标识

## Goal

降低同一重复系列在收件箱中的视觉占用，并让重复任务相较普通任务更容易被快速识别。

## Background

- 现有 Todo 展示投影只在“即将到来”中按 `seriesId` 折叠，收件箱仍会显示同一系列在 90 天窗口内命中的所有 occurrence。
- 折叠逻辑已遵循“先应用搜索、日期、清单、标签、优先级和状态筛选，再保留筛选结果中最近一条”的规则，可复用到收件箱。
- Todo 行已经统一普通任务和重复实例的内容结构；重复实例当前仅以双线左边框和描边“重复”徽标区分，辨识度较弱。

## Requirements

1. 收件箱中的重复 occurrence 按 `seriesId` 折叠，每个系列只显示当前筛选结果中日期最近的一条；普通任务继续逐条显示。
2. 折叠必须发生在所有现有筛选之后，避免更早但不匹配的 occurrence 遮蔽后续匹配项。
3. 折叠仅改变 Todo 列表展示，不写入数据、不改变 occurrence 投影、系列推进、日历或其他业务语义。
4. 重复任务在收件箱、今天、即将到来和自定义清单等 Todo 列表中统一使用更醒目的样式：使用带重复图标与“重复任务”文字的实心强调徽标，并为整行增加轻量强调底色/边框；不能仅靠颜色表达，也不能覆盖完成/跳过状态。
5. 保持重复实例现有的当前实例、未来只读和历史只读操作边界。

## Acceptance Criteria

- [x] 同一系列在收件箱命中多个 occurrence 时只显示日期最近的一条，不同系列各显示一条。
- [x] 搜索或日期等筛选只命中系列的后续 occurrence 时，显示该后续 occurrence，而不是整组消失。
- [x] 收件箱中的普通任务数量和排序语义不受系列折叠影响。
- [x] 重复任务行具有可见的重复图标、“重复任务”文字和轻量强调容器，比当前双线边框加描边“重复”徽标更醒目。
- [x] 醒目标识在所有 Todo 列表中保持一致；只有收件箱新增系列折叠，其他页面维持现有折叠语义。
- [x] 相关纯投影和组件行为有回归测试；format、lint、typecheck、全量测试和生产构建通过。

## Out of Scope

- 修改数据库 schema、重复规则、occurrence key 或物化策略。
- 在列表中增加展开全部 occurrence 的交互。
- 改变日历中的逐项展示。

## Key Decisions

- 收件箱复用“即将到来”的筛选后折叠规则，但不新增手动展开能力。
- 重复任务醒目标识统一应用于所有 Todo 列表，采用“实心图标文字徽标 + 轻量行强调”；日历与恢复页不在本次视觉调整范围内。
