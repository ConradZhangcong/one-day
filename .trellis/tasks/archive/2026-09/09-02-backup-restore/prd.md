# 备份与恢复

## Goal

让本地优先用户能把 One Day 的全部可恢复领域数据导出为一个可审计的 JSON 文件，并在当前或全新浏览器数据库中安全整库恢复；任何格式、版本、引用或写入错误都不得改变原有数据。

## Background

- 当前数据只保存在浏览器 IndexedDB；清除站点数据、卸载浏览器/PWA 或设备损坏可能造成永久丢失。
- 数据库当前为 Dexie v3，包含普通任务、重复系列、发生记录、清单、标签、提醒、长期目标、设置和内部元数据。
- 既有 MVP 设计已确定 `one-day-backup` v1、导入前完整校验与摘要确认、只做整库替换、失败全量回滚。
- 备份文件可能包含标题、备注、标签、时间和历史记录等敏感信息，导出界面必须明确提醒用户妥善保存。

## Requirements

1. 导出格式固定为 `format: "one-day-backup"`、`version: 1`，并包含 UTC `exportedAt`、导出时的应用 IANA `timeZone` 和完整 `data`。
2. `data` 包含普通任务、重复系列、发生记录、全部清单、标签、提醒、长期目标及可恢复设置；不得包含 IndexedDB 索引投影、临时 UI 状态、缓存、Service Worker 状态或其他运行时派生值。
3. 导出必须从一个一致的数据库快照读取，使用领域实体而不是 Dexie record 形状；文件名包含可识别的 One Day 标识和导出日期时间。
4. 导入边界接收 `unknown`：先解析 JSON，再按格式和版本路由，通过共享 Zod schema 一次性解码每个实体和设置。
5. 导入还必须校验跨实体引用与不变量，包括规范系统收件箱、唯一 id/key、任务和系列的清单/标签/目标引用、发生记录的系列引用、提醒 owner 引用、系列 active occurrence 关系及应用时区一致性。
6. 不支持的格式或版本、损坏 JSON、重复键、非法实体或悬空引用必须返回稳定错误，不得进入写事务。
7. 校验成功后先展示替换摘要，至少列出各类数据数量、备份导出时刻和时区；只有用户明确确认才允许恢复。
8. v1 仅支持整库替换，不支持合并、挑选类别、自动覆盖或从未来版本降级导入。
9. 恢复必须在一个覆盖所有持久化表的 Dexie 事务中清空并写入；任一清空、编码或写入失败都完整回滚，保留恢复前数据。
10. 成功恢复后重新建立规范系统数据、发布应用数据变更信号，并重新协调提醒；失败时不得发布成功失效信号或刷新为部分状态。
11. 设置页提供“导出备份”和“从备份恢复”入口，导入使用本地 `.json` 文件，确认文案明确当前数据会被替换且操作不可撤销。
12. 选择文件、预览、取消、确认、成功和失败流程在桌面与手机宽度、键盘操作和屏幕阅读器标签下可用；失败后保留可理解的错误信息，不显示原始敏感内容。

## Acceptance Criteria

- [x] 导出的 JSON 通过 v1 schema，包含所有当前领域实体和可恢复设置，不包含数据库索引投影或运行时缓存。
- [x] 非空数据库导出后可恢复到干净数据库；再次导出得到语义等价的数据，所有 id、occurrence key、revision、历史、提醒状态和本地时间值保持不变。
- [x] 恢复前展示准确的分类数量、导出时刻和时区；取消确认不产生任何数据库写入。
- [x] 非法 JSON、错误 format、未知 version、重复 id/key、非法领域值和任一悬空引用均在写入前被拒绝，现有数据库逐表保持不变。
- [x] 模拟事务中途失败时清空和已写入数据全部回滚；成功路径不会残留备份外的旧实体或设置。
- [x] 成功恢复后系统收件箱保持规范，当前页面/其他标签页可重新读取数据，提醒队列按恢复后的数据 reconcile 且不会因恢复流程重复通知。
- [x] 设置页可完成导出、选择 JSON、预览、取消和危险确认恢复；错误使用稳定中文文案，核心操作支持键盘和移动布局。
- [x] format、lint、typecheck、领域/应用/数据库/UI 测试和生产构建通过。

## Out of Scope

- 自动定时备份、云备份、账号、多设备同步、外部存储连接和加密托管。
- 增量备份、数据合并、冲突解决、分类恢复、导入任意第三方待办格式。
- 支持尚未定义的未来备份版本；未来版本通过新增显式迁移路由实现，不原地改变 v1。
- PWA 安装、离线重启和全浏览器发布加固；这些保留为后续独立任务。
