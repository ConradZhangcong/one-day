# 增加清空本地数据功能

## Goal

在设置页“本地数据”区域提供一个明确、难以误触且事务安全的清空入口，让用户可以主动删除当前设备上的 One Day 数据，并在成功后回到可继续使用的空白初始状态。

## Background

- 当前设置页的“本地数据”卡片已支持完整备份导出和整库恢复，但没有主动清空入口。
- IndexedDB v3 包含普通任务、重复系列、发生历史、清单、标签、提醒、长期目标、设置和内部元数据。
- `DexieBackupRepository.replaceAll()` 已证明可以在 `UnitOfWork.write` 覆盖全部表的单一事务中整库替换，失败时由 Dexie 全量回滚。
- 空白可用状态仍必须包含规范 `system:inbox`，并需要合法的应用时区；不能简单逐表清空后让已挂载页面读取缺失系统数据。
- 成功事务会发布应用变更信号；提醒运行时还必须重新协调，防止内存中的旧提醒继续触发。

## Requirements

1. 设置页“本地数据”卡片增加独立的危险操作区域，清楚说明删除不可撤销，并建议用户先导出备份。
2. 清空必须经过显式二次确认；打开、取消确认不得写数据库，确认期间禁用重复提交。
3. 清空覆盖所有用户内容及关联历史，且在一个覆盖全部持久化表的事务内完成；任一步失败时原数据完整保留。
4. 清空采用完整“恢复全新安装”语义：删除普通任务、重复系列、发生历史、自定义清单、标签、提醒、长期目标、应用偏好和内部元数据；不保留此前的应用时区或全天计划提醒时间。
5. 成功后建立可用的空白初始状态，包括规范系统收件箱，并使用当前设备 IANA 时区重新初始化应用；全天计划提醒时间回到产品默认值。
6. 成功事务发布一次应用变更通知并重新协调提醒，使当前页和其他标签页刷新为空状态，旧提醒计时器被取消。
7. UI 只调用应用服务，不直接访问 Dexie；成功与失败使用明确中文提示，失败时不假装数据已删除。

## Technical Notes

- 优先复用现有 backup repository 的全表事务和领域投影写入能力，避免另建一套容易漏表的删除清单。
- 需要应用/仓储/UI 测试覆盖成功、取消、重复点击、事务回滚、默认数据重建及提醒刷新。

## Acceptance Criteria

- [ ] 用户可在设置页找到“清空本地数据”，且危险性、不可撤销性和备份建议在确认前可见。
- [ ] 未确认或取消确认不会产生任何持久化写入。
- [ ] 确认后所有约定范围内的数据被原子清除；系统收件箱和必要初始设置处于合法状态。
- [ ] 注入中途失败时所有表保持清空前状态，应用不发布成功提示。
- [ ] 成功后当前页及其他 live-query 页面刷新为空状态，旧提醒不会继续调度。
- [ ] format、lint、typecheck、应用/数据库/UI 测试和生产构建通过。

## Out of Scope

- 删除浏览器站点权限、Service Worker 缓存、通知授权或浏览器自身设置。
- 云端删除、账号注销、自动清理或选择性按类别删除。
- 未经用户确认自动清空损坏或旧版本数据库。
