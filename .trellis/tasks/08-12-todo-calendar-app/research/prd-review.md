# PRD 收敛审阅

## 结论

在用户确认“一层清单 + 多标签 + 四档优先级 + 渐进填写”后，没有剩余的产品范围阻塞项。可以进入技术设计与实施规划，但仍需通过最终规划摘要获得一次新的实施批准。

以下隐藏问题可以在技术设计中确定，不需要继续向用户逐项提问；它们必须出现在最终摘要中，让用户通过整体审批确认：

1. 重复系列以计划时间为优先锚点；没有计划时间时才以截止时间为锚点。
2. `错过计划` 与 `已逾期` 是派生状态，不持久化；同时满足时只进入逾期主分组，避免重复。
3. 第一版备份恢复采用整库替换并保证事务回滚，不做合并导入。
4. 支持的浏览器以 feature detection 和测试矩阵定义；不承诺浏览器本身没有的 PWA 安装/通知能力。
5. 未来重复投影只读，只有当前活跃实例可完成、跳过或单次改期计划/截止；重复实例完成后第一版不可撤销。
6. 页面可见且浏览器允许执行时，提醒按 60 秒容差与持久 delivery key 验收；恢复只补发 15 分钟内的提醒。

## 一致性检查

- 目标与用户：明确服务个人轻量规划用户，并明确排除企业协作、重项目管理、纯习惯和重 GTD 作为第一版重点。
- 范围：R1–R6 覆盖记录、时间、重复、日历、恢复、数据/PWA；后续路线图与明确暂缓一致。
- 时间：计划执行和截止时间分离，并有对应 AC2、AC3、AC9。
- 重复：固定日历周期、单活跃实例、未来投影只读、不累计漏做、按完成时间重复后置，并有 AC4–AC6、AC13、AC14。
- 平台与数据：Web/PWA、本地优先、无账号、版本化备份、可测提醒窗口和关闭后限制，并有 AC15–AC17。
- 组织模型：一级清单、多标签、四档优先级、渐进填写、无项目层级，并有 AC18。
- 未发现相互矛盾的第一版/后续版条目。

## PRD 收敛修订建议

最终收敛时应做以下最小调整：

- 将重复出现在“已确认决策”和 R1–R6 的事实合并，保留前者作为简短决策摘要，详细行为只放 R1–R6。
- 明确错过计划与逾期是派生视图，而非额外生命周期状态。
- 明确重复锚点和无日期任务启用重复前必须选择首次发生日期。
- 将“轻量每日或每周回顾”收窄为只读汇总，不引入日记或统计仪表盘。
- 增加备份恢复的可观察行为：校验后整库替换、失败回滚、成功后记录格式版本。

## 建议实施边界

建议当前规划任务作为第一版父计划，实际交付拆为以下可独立验证的阶段；是否创建 Trellis 子任务可在正式实施前决定：

1. 工程与领域地基：PWA 骨架、设计令牌、领域时间类型、数据库 schema、测试设施。
2. 基础待办闭环：快速新增、清单/标签/优先级、编辑、完成/撤销、基础列表和搜索筛选。
3. 时间与恢复：计划/截止、派生状态、今天/未来/错过/逾期、提醒运行时。
4. 重复事项：固定规则、预览、单活跃实例、例外、暂停/恢复和边界测试。
5. 日历投影：议程、日、周、月、年及列表—日历一致性和拖拽改期。
6. 数据与发布：版本化备份恢复、离线/安装/升级、响应式、无障碍和跨浏览器验收。

每个阶段都必须以领域测试和可操作 UI 闭环结束，不能先铺完所有页面再补数据正确性。
