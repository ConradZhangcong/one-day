# 个人待办日历应用 — 第一版产品需求文档

## 目标

开发一款以待办事项为核心的个人轻量规划应用，帮助用户快速记录任务、安排计划执行时间、管理截止时间、可靠处理固定重复事项，并通过议程、日、周、月、年视图理解和调整个人时间负载。

第一版必须形成完整闭环：记录 → 整理 → 安排 → 提醒 → 完成、跳过或重新安排 → 回顾。头脑风暴中的增强功能全部保留在后续路线图，但不得拖慢或复杂化第一版。

## 目标用户与价值

### 核心用户

第一版服务“个人轻量规划用户”：希望统一管理工作、学习和生活待办，需要可靠重复规则和多维日历，但不希望先学习复杂 GTD 或企业项目管理体系的职场人士、学生、自由职业者及普通个人用户。

核心价值：

- 几秒内记下一件事，不被复杂字段打断。
- 看清今天要做什么、本周是否过载、截止事项集中在哪里以及长期节奏如何。
- 使用易理解的固定重复规则，无需掌握专业日历语法。
- 错过计划或截止后得到明确、无压力的恢复入口。
- 默认流程保持简单，同时允许逐步补充清单、标签和优先级。

### 第一版核心场景

- 快速记录无日期任务，稍后整理。
- 早晨查看今天计划、当天截止和需要恢复的任务。
- 创建每周例会、每月账单等固定周期事项。
- 在周视图比较每天负载并调整计划。
- 在月视图观察截止事项集中程度。
- 在年视图回顾任务密度和完成节奏。

### 第一版不重点服务

- 需要权限、分工、审批和团队报表的企业团队。
- 需要多层依赖、资源分配和关键路径的专业项目管理用户。
- 主要关注连续打卡、漏做率和习惯统计的纯习惯用户。
- 要求高度自定义情境、领域和工作流的重度 GTD 用户。

相关能力保留在后续路线图，但不能改变第一版低学习成本、快速完成日常规划的默认体验。

## 已确认的范围决策

- 第一版交付响应式 Web/PWA，不恢复 Git 历史旧原型代码。
- 第一版本地优先、无需账号，设备本地数据库是唯一事实来源。
- 第一版按 R2 的 60 秒容差保证页面可见且浏览器允许执行时的提醒；进入受限后台、挂起或完全关闭后仅在平台允许范围内尽力提醒。
- 第一版使用一级清单、多标签、无/低/中/高优先级，不建立独立项目层级。
- 后续 AI 只能提出可解释建议，不得静默改变用户日程。
- 本任务及后续规划文档使用中文。

## 产品原则

### 渐进式呈现

只输入标题即可创建任务；高级字段和未来增强能力不能挤占快速新增流程。

### 显式恢复

应用不得静默把错过计划或逾期任务移动到今天，必须保留原始时间并提供明确操作。

### 可预测重复

规则保存前展示未来发生日期；所有操作明确影响当前实例还是整个系列。

### 同一事实来源

列表和所有日历视图必须对同一任务、发生实例和状态给出一致结果。

### 用户控制数据与自动化

用户数据默认留在设备；导出、恢复、未来同步和未来 AI 均由用户主动控制。

## 第一版需求

### R1. 快速记录、组织与生命周期

- 快速新增默认只显示必填标题，以及常用计划/截止时间入口。
- 每个任务属于且只属于一个一级清单；未选择时进入系统“收件箱”。
- 用户可创建、重命名、排序和归档自定义清单；系统收件箱不可删除。
- 删除自定义清单前必须确认；其中未删除任务和重复系列移动到收件箱，不得级联丢失。
- 每个任务可添加零个或多个标签。
- 优先级为无、低、中、高四档，默认“无”。
- 备注、清单、标签和优先级在详情或展开区渐进填写。
- 第一版不提供独立项目实体、嵌套清单或子任务。
- 用户可编辑和明确删除任务，标记完成或跳过；普通单次任务可撤销完成，重复实例完成后已推进系列，第一版不提供撤销完成。系统记录实际完成/跳过时间。
- 持久生命周期只包含待处理、已完成、已跳过；错过计划和已逾期由时间动态推导。
- 提供收件箱、今天、即将到来、错过计划、已逾期和已完成视图。
- 支持文本搜索，以及日期、清单、标签、优先级、生命周期的组合筛选。

### R2. 计划执行时间、截止时间与提醒

- “计划执行时间”和“截止时间”是独立概念，均可不设置、设置本地全天日期或具体本地日期时间。
- 计划执行时间回答“准备什么时候做”，决定任务在计划日历中的位置。
- 截止时间回答“最晚什么时候完成”，决定何时逾期。
- 任务可只设置其中一个、同时设置两个或两者都不设置。
- 同时设置时，截止不得早于计划；同一天的全天/精确时间组合允许保存，并在界面清楚解释。
- 没有计划日期的任务不作为已安排事项进入日/周时间轴。
- 只有截止时间的任务以截止标记出现在对应日期，不伪装成执行时间块。
- 同时存在时，日历展示计划位置并独立提示截止信息。
- 全天截止在本地日期结束后逾期；精确截止在对应时刻经过后逾期。
- 全天计划在本地日期结束后才算错过；精确计划在对应时刻经过后算错过。
- 计划时间经过但截止未到时属于“错过计划/待重新安排”，不属于逾期。
- 提醒可明确关联计划或截止，并支持提前偏移；全天提醒使用用户可配置的默认本地时间。
- 稍后提醒只改变通知触发时间，不得修改计划或截止。
- 通知权限只能在用户主动启用提醒时请求；拒绝、撤销或浏览器不支持时，核心功能仍可使用并显示提醒状态。
- 页面可见、事件循环正常且浏览器仍允许执行时，提醒不得早于目标时间，并应在目标后 60 秒内触发；同一调度版本至多触发一次。
- 应用恢复执行时，只补发过去 15 分钟内尚未送达的提醒；更早提醒不再弹出陈旧系统或应用内通知，任务仍按当前计划/截止状态留在今天、即将到来或既有恢复视图。
- 进入受限后台、挂起、完全关闭或被操作系统终止后只做平台允许范围内的尽力提醒；设置界面必须说明限制。

### R3. 固定重复事项

- 支持每 N 天、N 周、N 月或 N 年的固定日历周期。
- 每周可选择一个或多个星期几。
- 第一版重复计算与周视图统一按 ISO 周：周一为每周第一天，星期编号为 1（周一）至 7（周日）；自定义每周起始日留待后续。
- 每月必须区分固定日期和“每月最后一天”。
- 规则可永久生效，也可按包含当天的结束日期或发生次数结束。
- 保存前最多预览未来三次发生日期；若结束日期或次数限制只剩一至两次，则显示全部剩余日期并明确规则即将结束。
- 有计划时间时，以计划时间为系列发生锚点；否则以截止时间为锚点。
- 计划和截止都未设置时，启用重复前必须选择首次发生日期；该选择直接成为计划执行时间（默认全天，也可选择具体时间），并作为系列锚点。
- 同时具有计划和截止时，每次发生保持二者的本地日历/墙上时间关系。
- 支持暂停和恢复整个系列；暂停期间从待办、日历和提醒队列隐藏该系列，但保留唯一活跃实例和历史，恢复后重新显示并按原相位继续。
- 当前实例可完成、跳过或单次改期计划/截止，且不改变固定周期相位；标题、备注、清单、标签和优先级只允许编辑整个系列。
- 尚未成为当前活跃实例的未来发生项只做只读预览，不能提前完成、跳过或单次改期；需要改变未来安排时编辑整个系列。
- 普通重复系列任意时刻最多只有一个活跃待处理实例。
- 连续错过多个发生日期时，不生成多条独立逾期任务；当前活跃实例保留原始日期并进入恢复区。
- 处理活跃实例后，寻找既严格晚于该实例原始锚点、又严格晚于当前时间/本地日期的下一合法发生项；不补发已经过去的未物化实例，有限规则没有下一次时系列自然结束。
- 只记录用户明确完成或跳过的实例历史；未物化漏过日期不计独立统计。
- 当前活跃实例的计划/截止编辑和改期必须明确标为“仅本次”；修改系列模板或规则必须再次确认其影响整个系列。
- 单次改期以原始发生日期作为稳定身份，后续周期不受影响。
- 修改整个系列时保留过去历史，只重算未来。
- 停止整个系列时归档系列、移除当前待处理实例并停止未来投影，已完成/已跳过历史继续保留；当前待处理实例不伪记为完成或跳过，永久删除系列历史必须经过单独的危险操作确认。
- 固定每月 29/30/31 日遇到不存在日期时跳过该月；“每月最后一天”单独计算。
- 每年 2 月 29 日在非闰年跳过。
- 第一版不支持按实际完成时间重复、“本次及以后”、节假日顺延或农历重复。

### R4. 议程与多维日历

- 议程视图按日期连续列出已逾期、错过计划、当前和未来事项。
- 日视图包含全天区和时间轴；没有时长的事项显示为时间点，不虚构时长。
- 周视图显示七天、全天计划行、定时事项和可比较的每日负载。
- 月视图每个日期显示有限数量标签，超出后显示 `+N` 并支持展开。
- 年视图通过热力图或紧凑标记展示负载密度和完成活动，点击日期可下钻。
- 用户可从各视图创建或打开任务；普通任务和当前活跃重复实例可完成、跳过或重新安排。
- 未来重复投影只读；拖动普通任务或当前活跃重复实例执行单次改期，系列修改必须再次确认。
- 可按已完成状态、清单、标签和优先级筛选。
- 状态含义不能只依赖颜色，必须辅以文字、图标或形状。
- 日/周/月/年中的“计划负载”统一定义为对应本地日期内待处理计划实例数量；“完成活动”统一定义为对应本地日期内实际完成的任务或重复实例数量。

### R5. 恢复与轻量回顾

- 错过计划和逾期是根据当前时钟推导的视图，不是额外持久状态。
- 错过计划保留原计划时间；逾期保留原截止时间。
- 同一任务同时满足两者时，只进入“已逾期”主恢复分组，详情仍显示计划已错过，避免重复。
- 两个恢复分组均提供完成、跳过和重新安排操作。
- 保留完成/跳过历史。
- 第一版提供只读日/周回顾：展示已完成、已跳过、错过计划和仍逾期的数量及事项列表；不引入日记或复杂统计仪表盘。

### R6. 本地数据、PWA 与基础可用性

- 第一版以响应式 Web/PWA 交付，在桌面和手机宽度提供一致核心能力。
- 用户可在平台支持时安装 PWA，并以独立窗口或接近应用的方式启动。
- 无需注册、登录或创建账户。
- 任务、系列、实例、设置和历史保存在当前设备本地数据库中。
- 除用户主动导出外，第一版不得上传任务内容。
- 首次成功加载后，任务增删改、完成、重复计算和日历浏览可离线使用；首次加载和版本更新可依赖网络。
- 已缓存应用外壳和本地数据在断网重启后仍可打开。
- 用户可导出带格式版本、导出时刻和时区的完整 JSON 备份。
- 恢复前必须校验格式和数据，展示将被替换的数据摘要并确认。
- 第一版恢复采用整库替换，不做合并；任何失败必须完整回滚并保留原数据。
- 界面说明清除站点数据、卸载或设备损坏可能造成数据丢失，并引导定期备份。
- 日期和重复使用用户级 IANA 时区；全天日期不得因 UTC 转换或旅行移动到其他日期。
- 应用不跟随设备时区静默改变计划；用户主动修改应用时区时确认并重算提醒。
- 核心流程支持键盘、文字缩放、浅/深色和非颜色状态表达。
- 核心 Web 功能覆盖实施时稳定 Chrome、Edge、Firefox、Safari；手机布局覆盖 Android Chrome 和 iOS Safari。PWA 安装/通知按平台能力渐进增强。

## 各视图职责

| 视图 | 主要问题 | 必须展示 |
|---|---|---|
| 议程 | 接下来做什么，包括恢复事项？ | 连续时间列表及恢复操作 |
| 日 | 今天具体执行什么？ | 全天区、详细本地时间轴、截止标记 |
| 周 | 本周安排是否均衡？ | 七日计划与每日负载对比 |
| 月 | 截止和繁忙日期集中在哪里？ | 紧凑标签、密度、`+N` 下钻 |
| 年 | 长期节奏如何？ | 热力图、完成或负载趋势、日期下钻 |

## 第一版明确暂缓

- 按完成时间重复、完整 RFC 重复规则、节假日调整、农历、单任务独立时区。
- 用户账户、自动云备份、多设备同步、冲突解决、服务端可靠后台推送。
- 原生移动/桌面端、外部日历双向同步。
- 项目层级、嵌套清单、子任务、依赖、附件、团队权限、指派、评论。
- 习惯连续记录、日记、番茄钟、四象限、倒计时、看板、甘特图。
- AI 分析、自动排程或任何未确认的数据上传。

以上能力不是取消，而是保护第一版边界。

## 后续路线图

### 快速记录与执行

- 自然语言日期/重复解析、语音输入、主屏组件、全局快捷键、分享入口、浏览器扩展和任务模板。
- 计划时长、多日时间块、拖拽创建/缩放、容量与冲突提示、精力/情境筛选。
- 多次/持续/位置提醒、专注模式、番茄钟、四象限、倒计时、看板和时间线。

### 项目、习惯与反思

- 子任务、项目结构、长期目标、里程碑、依赖和进度跟踪。
- 习惯独立实例、连续记录和漏做率。
- 日记、心情、回顾模板、完成趋势和拖延分析。

### 数据、平台与集成

- 加密云备份、账号和多设备同步。
- 服务端调度/Web Push 提升关闭后的提醒可靠性。
- 外部日历先只读订阅，再评估 Google/Outlook 双向同步。
- JSON/CSV/ICS 更广泛导入导出、原生移动/桌面端和平台通知。

### 协作与 AI

- 共享清单、指派、评论、活动历史和权限。
- AI 从文字/语音提取任务，提供可解释的优先级、冲突、负载和恢复建议。
- 任何自动排程或改期都必须由用户确认。

### 个性化与无障碍

- 主题、日历密度、每周起始日、更多日期格式和附加时区。
- 屏幕阅读器深化、减少动效、色觉友好配色和扩展快捷键。

## 验收标准

- [ ] AC1：首次用户无需打开高级设置，即可创建只有标题的任务、在收件箱找到它、添加计划或截止并完成。
- [ ] AC2：无日期、全天计划、精确计划、仅截止以及同时有计划/截止的任务出现在正确列表和日历位置；非法时间顺序不能保存。
- [ ] AC3：计划已过但截止未到只显示“错过计划”；截止经过后进入“已逾期”，同一任务不重复出现在两个恢复主列表。
- [ ] AC4：重复规则预览与议程、日、周、月、年对同一范围生成一致 occurrence key；查询起点不改变相位或 COUNT。
- [ ] AC5：只有当前活跃重复实例可完成、跳过或单次改期，且不会改变后续固定周期；未来虚拟投影只读。
- [ ] AC6：当前活跃实例的单次编辑/改期与整个系列修改具有明确范围；系列修改或停止保留既有完成/跳过历史，永久删除历史需独立确认。
- [ ] AC7：议程、日、周、月、年分别满足上文职责并可下钻到任务详情；所有负载/完成汇总按统一计数定义并与明细数量一致。
- [ ] AC8：列表变更立即一致反映到所有相关日历视图，日历操作也通过同一任务事实来源反映回列表。
- [ ] AC9：错过计划和逾期均保留原时间，并可明确完成、跳过或重新安排。
- [ ] AC10：核心数据在应用重启后存在，核心流程离线可用，状态含义不只依赖颜色。
- [ ] AC11：移动和桌面宽度均可完成核心流程，并支持键盘和可访问文字缩放。
- [ ] AC12：后续能力保持文档化；未显式修订本 PRD 时不得进入第一版。
- [ ] AC13：普通重复系列连续漏做时最多一个活跃实例；处理后直接推进到下一未来日期，不产生逾期堆积。
- [ ] AC14：第一版重复始终按固定日历周期计算，提前或延迟完成不会改为相对完成时间。
