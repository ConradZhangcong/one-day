# 个人待办日历应用 — 第一版实施计划

## 实施原则

- 先建立领域正确性和可测试契约，再铺设页面。
- 每个阶段必须形成可操作、可验证的小闭环，不留“最后再补测试”。
- 列表与所有日历视图只能消费同一投影。
- 不恢复旧原型代码，不提前实现 PRD 暂缓项。
- 任何实质产品范围变化都返回规划阶段并重新获得用户批准。

## 建议任务结构

当前任务保留为第一版总规划。正式实施可按以下阶段创建 Trellis 子任务；每个子任务拥有独立 PRD 摘要、验收、检查和提交：

1. 工程与领域地基。
2. 基础待办闭环。
3. 时间、恢复与运行期提醒。
4. 重复事项。
5. 多维日历。
6. 数据恢复、PWA 与发布加固。

阶段有顺序依赖，不建议并行修改共享领域模型；界面与测试夹具在契约稳定后可并行。

## 高风险文件与回滚点

| 区域 | 风险 | 回滚策略 |
|---|---|---|
| 时间值与重复 projector | 影响所有视图和提醒 | 单独阶段/提交；通过旧测试夹具保护 |
| Dexie schema 迁移 | 可能损坏本地数据 | 每版迁移夹具；禁止不可逆降级假设 |
| occurrence key/revision | 历史和例外可能失联 | 一经发布不得原地重定义，新增迁移版本 |
| 备份 schema | 用户长期可恢复性 | 只追加版本迁移，保留旧版本夹具 |
| service worker 缓存 | 用户可能卡在旧版本 | 显式更新、缓存命名版本化、生产回归 |
| FullCalendar 适配 | 拖拽可能绕过领域用例 | 适配器只发 command，禁直接持久化事件 |

## 完成定义

- AC1–AC18 全部通过并有自动或手工验收证据。
- 所有质量命令成功，生产 PWA 能安装且核心流程可离线运行。
- 导出备份能在干净数据库中完整恢复，失败路径不改变原数据。
- 重复规则、列表和五种日历视图对同一 occurrence key 行为一致。
- 已知 PWA 通知限制在产品内可见，没有超出 PRD 的承诺。
- 第一版没有引入暂缓功能或未审议的外部数据上传。
